# Crypto Service 0.0.9

## Highlights ⭐️

- **Private keys stay on the server**: crypto-server key generation returns a `keyId` and public key, and signing, decapsulation and sealed-box open take that `keyId`; exporting a key needs the `crypto:keys:export` scope. crypto-sdk and the crypto-mcp tools (now key handles) follow the same model. These are breaking API changes.
- **Stricter access control and errors**: every crypto-server route requires a named scope, JWTs must carry `exp` and `iat` within a maximum lifetime (and issuer and audience in production), KDF requests meet OWASP floors and run off the event loop, and every error is RFC 9457 `application/problem+json`.
- **PASETO v4.local that other libraries can read**: `v4local` now follows the PASETO v4 specification and reproduces the official test vectors. Tokens issued by 0.0.8 and earlier no longer decrypt and must be re-issued; v4.public is unaffected.
- **Packages and tooling**: every package has an `exports` map checked by publint and are-the-types-wrong, npm releases carry provenance, crypto-cli gains `hash`, `keygen` and `cbom` subcommands with `--json`, and the toolchain moves to ESLint 10, chai 6 and mocha 12.
