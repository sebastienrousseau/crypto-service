# crypto-service 0.0.37

## Highlights ⭐️

- **Security fixes in dependencies**: body-parser 2.4.0 fixes a high-severity denial of service (GHSA-27r3-jxmh-p828) reachable through express 5 in crypto-middleware; fast-uri 3.1.9 and 4.2.3 fix four advisories in the URI parsing used by fastify and ajv; serialize-javascript 7.1.3 fixes an XSS advisory in a test-only path. Workspace overrides now require the patched versions, so no affected version resolves.
- **A release that fails to publish can be published again**: the release workflow can be run by hand for an existing tag. It builds nothing: it downloads the tarballs attached to the release and refuses any whose version or SHA-256 does not match the release notes, so GitHub Packages and npm receive exactly the bytes listed below. This is how v0.0.36 reached both registries, after the two workflow bugs that stopped it were fixed.
- **Dependency updates**: pino 10.4.0 in crypto-server, React 19.3.1 for development (crypto-react still accepts React from 19.3.0), and github/codeql-action 4.39.1 in CI. OpenTelemetry stays on the 0.223 / 2.x line until `@fastify/otel` supports the 0.300 / 3.0 SDK.
