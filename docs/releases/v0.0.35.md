# crypto-service 0.0.35

## Highlights ⭐️

- **Stream chunk sizes validated**: in crypto-lib, `streamEncrypt` and `streamPqEncrypt` looped forever on `chunkSize: 0` and returned a stream with no chunks (dropping the plaintext) for `NaN` or a negative size. `streamMultiPqEncrypt` let `NaN` and fractional sizes through its range check, producing streams that could not be decrypted. All three now throw unless `chunkSize` is a positive integer. crypto-server was not affected: its route schemas only accept integer sizes in range.
- **Complexity baseline cleared**: all 23 recorded offenders are refactored, so every function meets cyclomatic ≤ 10, cognitive ≤ 15, Halstead difficulty ≤ 30 and ≤ 60 lines, and any new offender fails CI. Behaviour is unchanged.
- **Refactors pinned by recorded behaviour**: each refactor follows a test that records the code's output before the change (LSP and MCP responses, diagnostics, benchmark statistics, CLI help, CBOM validation, metering, STREAM wire layouts) and was checked to fail when that output changes.
