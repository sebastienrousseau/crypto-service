# crypto-service 0.0.36

## Highlights ⭐️

- **Security fixes across the family**: PGP `verify` now checks signatures, PASETO tokens are checked for expiry, PQXDH verifies pre-key signatures, and ECDSA and Ed25519 verification accept exactly the valid signatures. crypto-server closes cross-tenant KMS access, owner collisions, OPAQUE identifier squatting and private keys left on disk by v1 routes; the ORM packages refuse legacy ciphertext by default.
- **Post-quantum, standardised and native**: hybrid signatures are Composite ML-DSA and HPKE's post-quantum suite is X-Wing, with one combiner for every X25519 + ML-KEM-768 construction. ML-KEM, ML-DSA and SLH-DSA run natively on Node.js 24.7+, and 54 NIST ACVP known-answer tests check them against FIPS 203, 204 and 205.
- **Breaking changes, listed in the CHANGELOG**: every crypto-lib error carries a code, test hooks move to `@sebastienrousseau/crypto-lib/testing`, `createEncryptStream` uses a new streaming format, P-256 and P-384 ECDH return the standard shared secret, and MAC keys must be at least 16 bytes. Read the 0.0.36 section of CHANGELOG.md before upgrading.
- **Operable server**: crypto-server gains an audit log and `DOCS_ENABLED`, `/ready` fails when it should, telemetry starts only with a collector, and logs carry request IDs from one logger.
